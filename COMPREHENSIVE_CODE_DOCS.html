System Architecture

The system interacts with two primary databases and exposes 7 REST API modules.

Storage Layer

  • Supabase (PostgreSQL): Handling unstructured data, candidate profiles (auto_apply_cand), webhook configurations, and application logging.
  • Azure SQL Server: Executing complex business logic via Stored Procedures for Job Matching, Application Submission, and Recommendations.

Application Layer

  • FastAPI: Asynchronous web framework.
  • Asyncio: Used for parallel IO operations (e.g., checking multiple listing details concurrently).

Resume Intake Module

app/api/resume_intake/*

POST /resume-intake/process-resume

Method: process_resume_endpoint

Uploads and parses a resume file (PDF/DOCX/TXT).

Flow:

  1. Hashes file content for caching (Key: resume:{id}:{hash}).
  2. Extracts text from file.
  3. Uses LLM (GPT-4o) to structure data into JSON.
  4. Filename Normalization: Sanitizes filename to FirstName_LastName.pdf.
  5. Updates auto_apply_cand and parsed_cand_resume in Supabase.
  6. Generates vector embeddings (Qdrant) for search.

Parameters:

Param Type Description
file UploadFile The resume file (PDF, DOCX, TXT)
candidate_id int Target Candidate ID

GET /resume-intake/cache/stats

Returns memory cache statistics (hits, misses, size).

Apply Webhook Module

app/api/apply_webhook/*

POST /webhook/cand-job-matching

Method: webhook_listener

Core endpoint triggered by Supabase when a candidate matches a job.

Business Logic (Ordered):

  1. Validation: Checks payload type (INSERT) and table (cand_job_matching).
  2. Similarity Gate: Returns immediately if similarity_score < 0.7.
  3. Deduplication: Checks if application already exists in job_application_tracking.
  4. Active Check: Verifies is_active flag in auto_apply_agent_preferences.
  5. Daily Limit: Enforces daily_application_limit (Default: 10). Count is not cached for safety.
  6. Parallel Filtering (Async):
    • Fetches is_remote_preferred → Checks job is_remote_location.
    • Fetches Preferred_MinimumPayrate_PerHour → Checks job MinPayRate.
    • (Runs concurrently via asyncio.gather)
  7. Execution: Calls SQL SP Usp_SC_JobSeeker_IU_ApplyJob.
  8. Logging: Inserts record into job_application_tracking.

Recommendations Module

app/api/recommendations/*

GET /api/recommendations

Executes USP_AI_Get_JobSeekerRecommenededJobList.

Uses a custom Async Connection Pool to handle SQL Server connections efficiently.

GET /api/recommendations/{requirement_id}

Executes USP_AI_Get_JobSeekerRecommenededJobDetails to get full job description.

Requirement Details Module

app/api/requirement_details/*

GET /api/requirement/{requirement_id}

Fetches job details via Beta_usp_Get_Requirement_Details.

  • Caching: 5-minute TTL.
  • Rate Limit: Applied via slowapi.

Manual Apply Module

app/api/manual_apply/*

POST /apply-job

Allows manual application triggering. Bypasses similarity and daily limit checks.

Outreach Agent Module

app/api/outreach_agent/*

POST /webhook/outreach/job-match

Triggered when an application is created. Sends notifications.

  • Channels: Email (SendGrid), SMS (Twilio).
  • Template: HTML email with job details.
  • Concurrency: Uses asyncio.Semaphore to limit parallel notifications.

Candidate Sync Module

app/api/candidate_sync/*

POST /candidate-sync

Syncs candidate data between SQL Server and Supabase based on email.

Internal: Preferences Service

app/services/auto_apply_preferences/preferences_service.py

Key Functions

  • get_candidate_preferences(cand_id): Fetches prefs, creates default if missing. Cached.
  • check_daily_limit_reached(cand_id, limit): Queries DB for today's count. Not Cached.
  • create_default_preferences(cand_id): Sets default limit (10) and active status (True).
